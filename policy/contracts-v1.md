# V1 contract semantics

Status: Approved for Milestone 0

The JSON Schemas under `policy/schemas/v1` are the normative structural contracts. This document defines semantic invariants that require relationships across fields, state, or contracts and therefore are not delegated to JSON Schema alone.

Validation is two-stage: strict structural validation first, then bounded semantic validation. Failure at either stage produces a typed error and an `indeterminate` decision for a recognized mutating operation. An adapter must not repair, infer, or default a security-critical value.

## Common rules

- Input is UTF-8 JSON with a maximum envelope size and nesting depth set by the adapter before deserialization.
- Contract objects are immutable after validation.
- IDs are unique within their documented scope. UUIDs are generated by a cryptographically secure OS source; clients cannot choose trusted decision, error, or audit IDs.
- Timestamps are UTC for digest and comparison behavior. Clock uncertainty is evidence and can make expiry or freshness indeterminate.
- Digests are computed from the stated bytes/representation and compared in constant time when they protect authorization state.
- Text fields described as safe or redacted must pass redaction before persistence or user display. Schema-valid text is not automatically non-sensitive.

## OperationIntent

- `raw_request_digest` covers the exact bounded host input bytes accepted by the adapter.
- `normalized_operation.digest` covers the RFC 8785 canonical bytes represented by `canonical_json`; parsing and re-canonicalizing must reproduce the same bytes and digest.
- `resolution_status=complete` means every security-critical target, working-context value, tenant/environment identity, privilege, reversibility fact, and blast-radius fact required for this operation kind is established.
- Every `evidence_id` and recovery/precondition reference resolves to exactly one evidence/precondition entry. Duplicate fact or target IDs are invalid.
- Every `resolved` target has a non-null canonical ID and identity digest. An ambiguous, missing, or unsupported target cannot appear in an approval-eligible intent.
- Canonical path identities include the platform/filesystem comparison model. String equality alone is not target identity.
- `sensitive_fields` is complete for adapter-known sensitive locations but is not the only redaction control; pattern and canary detection still run before audit.

## Decision

- `allow` requires a supported operation, complete required resolution, a healthy immutable policy snapshot, no applicable external restriction, and a built-in allow rule that positively proves the supported safe case.
- `ask` requires a non-null `approval_requirement`; no other outcome may carry one.
- `deny` identifies at least one determining deny rule or a stable trusted integration rule that maps a security state to deny.
- `indeterminate` identifies a typed error or missing fact and cannot be cached or converted to allow.
- `determining_rules` contains every rule at the winning restriction level plus any built-in fact needed to explain the result. Diagnostics may separately list non-determining matches.
- `policy_snapshot_digest` covers the complete canonical immutable restriction union, including layer, bundle, version, authority/scope, and rules.
- `reevaluate_after` cannot exceed the earliest expiry among required evidence, policy, approval prerequisites, or trusted health state.

## Error

- `safe_message` and `metadata` never contain raw tool input, commands, payload bodies, paths configured as sensitive, credentials, authorization headers, stack traces, or environment values.
- Detailed internal diagnostics remain ephemeral or enter a separately protected developer channel only when trusted policy permits; they are not added to this contract dynamically.
- `security_disposition` is chosen deterministically from the error code and integration policy, not caller input.

## Policy bundle and composition

- Rule IDs are unique within a bundle. Effective rule identity is `(layer, bundle_id, bundle_version, rule_id)`.
- Empty selector dimensions are invalid; omitted dimensions mean unconstrained for that dimension.
- Present selector dimensions are ANDed. Values within one dimension are ORed. A required unavailable fact produces `indeterminate`, not no-match.
- `canonical_path_prefixes` are interpreted only after platform-aware canonical target resolution and boundary-safe prefix comparison; raw textual prefix matching is prohibited.
- All supplied bundles validate before atomic activation. Composition is set union, not recursive/directional merge. Order and input permutation do not change semantics or canonical snapshot digest.
- External rules return only `ask` or `deny`. There is no deletion, disable, waiver, negative selector, override, or priority operation.
- The final restriction is the join on `allow < ask < deny`. `indeterminate` remains an evaluation state outside that lattice.

## Audit event

- Audit construction receives a redaction-safe projection, not the raw intent or tool request.
- Actor, session, operation, and target references are domain-separated digests so equal source values cannot be correlated across field classes unintentionally.
- `event_type` transitions follow a state machine; later events cannot claim execution or verification without the required preceding decision/execution correlation.
- `canary_scan=failed` makes audit health unhealthy and prevents persistence of the suspect event in the ordinary sink.
- Audit storage must reject unknown fields and must not enrich an event with raw data.

## Compatibility

Consumers reject unsupported major versions. Minor-version acceptance requires an adapter explicitly tested for that minor version; `additionalProperties: false` prevents accidental forward acceptance. Contract migration produces a new object and digest and therefore invalidates prior approvals unless the approval protocol explicitly binds both representations under a future major version.
