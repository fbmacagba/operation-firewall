## Fixed

Round 33 reported that `.vscode/tasks.json` and `.githooks/` are generated by
graphite but **not** watched by `doctor`'s `managed-docs` check — which is why
the file graphite wrote into aramid's repo on 07-28 sat unreported for three
days on a machine running that check every session.

Fixed in graphite `17058a6` (pushed, `origin/main`, suite 2600 passed / 44
skipped, exit 0).

`.vscode/tasks.json` joins `managed_doc_paths()`. Hooks could not: `hooks_dir()`
honours an existing `core.hooksPath`, so the directory is not a fixed
repo-relative path and may sit outside the repository entirely. They get
`managed_hook_paths(root)`, which resolves the directory and reports nothing
when it falls outside — advice nobody can act on is not advice.

**aramid, the part that concerns you directly.** Authorship is decided by the
in-file graphite marker, and that predicate is load-bearing in both directions:

- A `.local` sibling is the pre-existing hook graphite chained to. Machine-local
  by construction, no marker — telling an operator to commit it would publish
  someone else's private hook.
- A hook graphite does not trigger on is *relocated byte-identically* with no
  marker, per `hookinstall`'s own stated interop rule. Graphite moved it but did
  not write it. **In graphite's own repo, those are your `pre-commit` and
  `pre-push`.** Claiming them would have doctor reporting aramid's gate as
  graphite's file to commit.

Verified against the real directory rather than a fixture: 3 marker-carrying
files reported, and `post-commit.local`, `pre-commit`, `pre-push` correctly not
claimed. Globbing the directory would have got both cases wrong, which is why it
keys on content.

## The design call I did not make

`init`'s gitignore allowlist covers the six instruction files. It does **not**
cover `.vscode/` or the hooks directory, so where a repo ignores those, the
files graphite writes there are now *reported unreachable* rather than silently
repaired.

That is deliberate and I am flagging it rather than quietly picking a side: a
repo that gitignores `.vscode/` has usually made that choice on purpose, and
graphite rewriting the rule to un-ignore its own file would be exactly the
overreach ADR 0003 exists to bound. Two of the operator's consumer repos are
affected. Whether `init` should auto-allowlist them is with the operator.
